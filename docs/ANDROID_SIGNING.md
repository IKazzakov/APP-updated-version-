# Подпись тестового APK

Версия клиента — 2.5.3. Рабочее приложение и main этим изменением не затрагиваются.

## Почему сборка остановлена

Для обновления установленного приложения Android требует прежний пакет и прежний ключ подписи. Его замена не позволяет установить APK поверх старого приложения. Гостевой профиль хранится с локальными учётными данными; удаление приложения может лишить пользователя доступа к этому профилю.

У прежнего тестового APK из коммита 87bea0f сертификат SHA-256:

`66902b5305769bb828cdea92df0206f7048ac37e8dd84dbb86b4d582225fb33c`

В старом workflow кэшировался `~/.android/debug.keystore`, хотя сборка использовала `work/android-user/debug.keystore`. Проверка восстановленного кэша в [CI](https://github.com/rojoscarlos-cpu/Test/actions/runs/39823570460) подтвердила отсутствие обоих файлов и других keystore в кэше Gradle. Копия старого ключа локально также не найдена. APK содержит открытый сертификат, но восстановить закрытый ключ из него нельзя.

Первый APK модульного клиента из CI 39821380013 подписан другим временным ключом. Он не подходит для обновления прежнего «Движение Тест». В public возвращена прежняя тестовая сборка; новая сборка ожидает решения по ключу.

## Постоянное хранение

- `android/staging-signing.json` хранит пакет, название и открытый отпечаток сертификата. Пока он соответствует прежнему «Движение Тест».
- Закрытый ключ хранится в резервной копии у владельца и в секрете репозитория GitHub Actions `STAGING_ANDROID_KEYSTORE_BASE64`. Он не должен попадать в git, журнал, клиентские assets или кэш.
- CI восстанавливает ключ во временный файл с правами 600. Кэшируются только зависимости Gradle. Веб-публикация staging после успешных проверок может продолжаться при остановленной Android-сборке; она использует проверенный исходный коммит и прежний APK.
- Локально путь задаётся `MOVEMENT_STAGING_KEYSTORE`; по умолчанию используется игнорируемый `work/signing/staging-debug.keystore`.
- `npm run build:apk:staging` проверяет открытый сертификат до изменения конфигурации/удаления прежнего APK и повторно проверяет подпись собранного файла до публикации. При отсутствии или несовпадении ключа сборка останавливается; новый ключ автоматически не создаётся.
- Для тестового debug-ключа используются alias `androiddebugkey` и пароль `android`. Пароль не заменяет защиту самого файла закрытого ключа. Основная сборка сохраняет прежнюю схему подписи.

## Два варианта продолжения

1. Если у владельца есть резервная копия прежнего ключа, сначала проверить её открытый отпечаток. При совпадении сохранить резервную копию и добавить секрет Actions. После этого можно собрать обновление с прежним пакетом и сохранить данные устройства.
2. Если копии нет, согласовать новый пакет тестового приложения и новый постоянный ключ. Такое приложение устанавливается рядом со старым, у него отдельный гостевой профиль и локальная очередь. Старое приложение и доступ к его профилю сохраняются. Автоматический перенос профиля по имени или приглашению не предусмотрен.

Смена пакета и отпечатка не выполняется автоматически. Удалять старое приложение для обхода ошибки подписи не требуется.

## Добавление секрета владельцем

1. Подготовить однострочный Base64 из согласованного файла ключа. Для Linux: `base64 -w 0 staging-debug.keystore > STAGING_ANDROID_KEYSTORE_BASE64.txt`; для macOS: `base64 < staging-debug.keystore | tr -d '\n' > STAGING_ANDROID_KEYSTORE_BASE64.txt`.
2. Открыть [Test → Settings → Secrets and variables → Actions](https://github.com/rojoscarlos-cpu/Test/settings/secrets/actions).
3. Нажать **New repository secret**. Имя: `STAGING_ANDROID_KEYSTORE_BASE64`. В **Secret** вставить содержимое подготовленного файла и сохранить.
4. Сохранить отдельную резервную копию ключа. Base64 и закрытый ключ в чат или репозиторий не отправлять.
5. Сообщить о готовности для повторного запуска тестовой сборки. Конфигурация сертификата должна соответствовать согласованному ключу.

Подключение GitHub в текущей среде позволяет обновлять исходники, но не предоставляет инструмент записи Actions secrets. GitHub CLI не авторизован для этой операции, поэтому добавление секрета требует действия владельца.
