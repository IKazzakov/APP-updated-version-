## Постоянное хранение

- `android/staging-signing.json` хранит пакет, название и открытый отпечаток сертификата. Он соответствует новому «Движение Тест UI».
- Закрытый ключ сохранён локально в `work/signing/staging-debug.keystore` с правами 600. Отдельно подготовлен частный архив `Movement-Test-UI-signing-backup.zip` для скачивания владельцем: ключ, его Base64 для Actions, открытый сертификат и инструкция. Архив нужно скачать и сохранить вне среды сборки. В GitHub Actions ключ ещё требуется добавить как секрет `STAGING_ANDROID_KEYSTORE_BASE64`; до этого автоматическая Android-сборка остановлена. Незашифрованные ключ, Base64 и исходный архив не должны попадать в git, журнал, клиентские assets или кэш. Для скачивания через интерфейс GitHub добавлена только AES-256 копия: [private-backups](../private-backups/README.md). Пароль передан владельцу отдельно в чате.
- CI восстанавливает ключ во временный файл с правами 600. Кэшируются только зависимости Gradle. Веб-публикация staging после успешных проверок может продолжаться при остановленной Android-сборке; она использует проверенный исходный коммит и уже подготовленный APK из public.
- Локально путь задаётся `MOVEMENT_STAGING_KEYSTORE`; по умолчанию используется игнорируемый `work/signing/staging-debug.keystore`.
- `npm run build:apk:staging` проверяет открытый сертификат до изменения конфигурации/удаления прежнего APK и повторно проверяет подпись собранного файла до публикации. При отсутствии или несовпадении ключа сборка останавливается; новый ключ автоматически не создаётся.
- Для тестового debug-ключа используются alias `androiddebugkey` и пароль `android`. Пароль не заменяет защиту самого файла закрытого ключа. Основная сборка сохраняет прежнюю схему подписи.

## Резервная копия и обновления

Архив содержит `staging-debug.keystore`, `STAGING_ANDROID_KEYSTORE_BASE64.txt`, `staging-certificate.der` и `README.txt`. Он предназначен владельцу. Тестировщикам передаётся только APK.

Перед выпуском сборка проверяет открытый сертификат из настоящего keystore и сертификат самого APK. Отсутствующий или чужой ключ не заменяет опубликованный файл. Проверка APK также подтверждает пакет, версию, права, локальные ML-ресурсы и отсутствие вложенного APK/закрытого ключа.

Для последующих версий хранить резервную копию вне этой временной среды и использовать тот же Actions secret. Новый ключ не генерировать. Восстановление из архива проверено сравнением файла ключа и декодированного Base64; публичный сертификат подтверждён keytool и apksigner.

## Добавление секрета владельцем

1. Скачать [зашифрованный архив через GitHub](../private-backups/README.md), войдя в аккаунт с доступом к репозиторию. Распаковать в 7-Zip/WinRAR с паролем из чата. Открыть готовый `STAGING_ANDROID_KEYSTORE_BASE64.txt` обычным текстовым редактором. Значение уже подготовлено, создавать новый ключ не нужно.
2. Открыть [Test → Settings → Secrets and variables → Actions](https://github.com/rojoscarlos-cpu/Test/settings/secrets/actions).
3. Нажать **New repository secret**. Имя: `STAGING_ANDROID_KEYSTORE_BASE64`. В **Secret** вставить содержимое подготовленного файла и сохранить.
4. Сохранить отдельную резервную копию ключа. Base64 и закрытый ключ в чат или репозиторий не отправлять.
5. Сообщить о готовности для проверки CI. Локальный APK уже готов; эта настройка нужна для будущих автоматических обновлений тем же ключом.

Подключение GitHub в текущей среде позволяет обновлять исходники, но не предоставляет инструмент записи Actions secrets. Доступная публикация исходников и APK не предоставляет запись Actions secrets, поэтому добавление секрета требует действия владельца.
