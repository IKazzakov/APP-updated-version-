# Счётчик упражнений

Русское приложение для одного человека: приседания и визуальные хлопки ладонями. Основная цель — Chrome на Samsung Galaxy S23 в вертикальном положении. Есть адаптивный интерфейс настольного Chrome, зеркальная передняя камера и переключение камеры. Обработка полностью в браузере; сервера распознавания, микрофона, записи и загрузки видео нет. Счётчики двух режимов живут в памяти вкладки до перезагрузки.

## Запуск

Нужен Node.js 22+ и npm.

```sh
npm ci
npm test
npm run build
npm run preview
```

Для разработки: `npm run dev`. `localhost` разрешает камеру в настольном Chrome. Для телефона используйте HTTPS, а не HTTP с локальным IP компьютера. Встроенный предпросмотр может ограничивать камеру: откройте прямую ссылку отдельной вкладкой Chrome. Настройки доступа определяются Sites. На момент обновления 1.4.1 владелец ранее переключил сайт на публичный доступ; обновление сохраняет текущую аудиторию.

## Пользование

1. Выберите «Приседания» или «Хлопки ладонями».
2. Нажмите «Начать» и разрешите **камеру**. Микрофон не запрашивается.
3. Подождите загрузки выбранной модели. После неё есть 2 секунды на подготовку, затем исходное положение должно устойчиво распознаваться. Статус «Готово» подтверждает его.
4. Приседания: телефон примерно в 2–3 м, устойчиво, на высоте таза; встаньте боком или под небольшим углом. Таз, колени, пятки и носки должны быть в кадре. Полное движение вниз и вверх даёт одно повторение после возврата.
5. Хлопки: телефон примерно в 1–1,5 м; встаньте лицом к нему, обе кисти перед грудью. Начните с разведённых ладоней. Сведите и снова разведите. Считаем движение ладоней, звук не используется.
6. «Пауза» сохраняет число и отбрасывает незавершённое движение. «Продолжить» требует заново подтвердить исходное положение. «Сбросить» обнуляет только текущий режим. Смена режима сохраняет отдельные числа.
7. «Выключить камеру» останавливает все дорожки видеопотока и Worker. При уходе в фон подсчёт ставится на паузу; после возвращения нажмите «Продолжить».

Не закрывайте лицо/тело плохим светом и не направляйте камеру против яркого окна. Если Full работает медленно, раскройте «Диагностика» и выберите Lite.

## Структура

- `src/camera.js`, `src/camera-profiles.js` — запрос без аудио, проверка фактически поддержанных профилей камеры, прекращение дорожек и защита от поздних ответов.
- `src/auto-profile.js` — измерение нагрузки и качества, частота модели и снижение нагрузки в безопасном промежутке.
- `src/frame-cadence.js` — расписание запусков без округления каждого интервала вверх до целого кадра камеры.
- `src/motion.js`, `src/motion.worker.js`, `src/optical-flow.js`, `src/frame-fusion.js` — отдельный быстрый поток обработки изображений и согласование с задержанными ответами модели.
- `src/models.js`, `src/vision.worker.js` — жизненный цикл моделей и распознавание в отдельном Worker. Классический Worker нужен для загрузчика WASM MediaPipe с `importScripts`; esbuild собирает его из закреплённого пакета.
- `src/algorithms/` — геометрия, сглаживание, извлечение признаков и конечные автоматы упражнений.
- `src/session.js` — независимые счётчики, пауза, сброс, отбрасывание устаревших результатов по номеру поколения.
- `src/main.js`, `src/ui.js`, `src/overlay.js` — управление, русский интерфейс и наложение точек.
- `src/diagnostics.js` — ограниченные журналы в памяти (80 событий, 12 ошибок), копирование только по нажатию.
- `src/config.js` — все пороги и временные настройки с пояснениями.
- `tests/` — проверки последовательностей движений, управления сеансом и камеры.
- `public/assets/models/manifest.json` — закреплённые источники, размеры и SHA-256 моделей.
- `.openai/hosting.json` — идентификатор Sites и статическая папка `dist`.

## Модели и ресурсы

`@mediapipe/tasks-vision` **0.10.32** (точная версия), Pose Landmarker **Full** по умолчанию, опционально **Lite**; Hand Landmarker — **две кисти**. Активна только модель текущего упражнения. Для приседаний сохранён CPU delegate в Worker. В режиме хлопков проверяется GPU через WebGL2/OffscreenCanvas в Worker; на первых восьми свежих кадрах сравниваются CPU и GPU (два прогрева, шесть замеров). GPU выбирается только при медианном времени минимум на 10% меньше CPU; проигравший экземпляр закрывается. Явно медленный программный GPU (два замера >100 мс и более чем втрое медленнее CPU) отключается после двух кадров, без полного сравнения. При недоступном GPU сразу используется CPU, при ошибке GPU во время работы выполняется автоматический переход на CPU. В диагностике показаны фактический delegate, оба времени и причина резервного режима. На время сравнения существуют два экземпляра Hand одной версии; после него работает один. Показатели детекции/присутствия/отслеживания Pose остаются 0,6; для Hand используются стандартные 0,5. Для Pose дополнительно проверяются `visibility`, доступная `presence` и границы кадра у нужных точек. У Hand Landmarker нет отдельного надёжного per-landmark visibility: используем ограничения Tasks, наличие двух полных наборов точек, конечность координат и размер/границы ладоней. Handedness определяет левую/правую руку, а не уверенность наличия кисти; оно записывается для диагностики и не отбраковывает координаты. Нулевое visibility кисти не скрывает её точки.

JS для Worker и оба варианта WASM (SIMD и без SIMD) копируются/собираются из одного npm-пакета при `npm run build`; зависимости закреплены также в `package-lock.json`. Модели, Worker, WASM и интерфейс размещаются **вместе** в `dist`; внешние CDN и внешние шрифты при работе не нужны. Сборка проверяет SHA-256 моделей и прекращается при несовпадении. Происхождение и лицензии см. `THIRD_PARTY_NOTICES.md`. Оригинальные модельные .task сохранены в Git, без LFS; это ZIP-пакеты TFLite, проверенные на CRC и сигнатуры.

Официальный сервер моделей Google ограничен сетевой политикой среды разработки. Поэтому использованы копии из закреплённых коммитов открытых репозиториев; точные адреса и локальные хеши документированы. Каждый .task фактически загружен и запущен в Chromium. Побайтовую сверку с официальным сервером в этой среде выполнить нельзя.

## Алгоритмы

**Приседания.** На лучше видимой стороне считаем угол таз–колено–голеностоп и вертикальную высоту таза над голеностопом, нормированную на сумму длин бедра и голени. Высоту стоя запоминаем после устойчивого прямого положения. Раздельные пороги: стоя ≥160°, начало опускания <145°, низ ≤108° **и** падение нормированной высоты таза ≥0,16. Возврат — угол ≥160° и остаточное падение <0,09. Низ и возврат подтверждаются временем, минимальный цикл 650 мс. Малые покачивания внизу не переармируют счётчик. Один только наклон с прямыми коленями не проходит оба признака. При смене видимой стороны движение сбрасывается, требуется стоя. Пуск сидя не считается повторением.

**Хлопки (1.4.1).** Центр ладони — среднее запястья и четырёх MCP-точек. Геометрия вычисляется в общих пиксельных координатах изображения. После устойчивого разведения в течение 350 мс фиксируются медианные расстояние и масштаб ладоней. Масштаб не меняется внутри движения: поворот ладони ребром и медленное сближение не сдвигают нормализацию. После завершённого движения его можно обновить при новом устойчивом разведении. Отдельные WorldLandmarks для расстояния между кистями не используются.

Автомат проходит `baseline → open → approaching → closed → reopening → open`. После начальной подготовки не нужно удерживать крайние положения. Для каждого цикла отслеживается свой максимум расстояния. Подход начинается после уменьшения на 0,3 исходного масштаба; близость требует реального наблюдения двух кистей, сокращения минимум на 0,7 и расстояния ≤min(1,9; 75% максимума этого цикла). Разворот подтверждается увеличением на 0,2. Возврат засчитывается в первом подходящем кадре с движением наружу и расстоянием ≥max(1,2; минимум + ограниченное увеличение). Увеличение равно 40% размаха текущего цикла с границами 0,55–0,8 масштаба ладони. Нет прежней выдержки 35 мс, требования двух кадров на крайней точке или возврата к 80% первоначального широкого разведения. Двигаться может одна или обе руки. Минимальная наблюдаемая часть цикла — 70 мс, интервал между наблюдавшимися минимумами засчитанных движений — 100 мс; поздний возврат после перекрытия не отбрасывает следующий настоящий цикл, таймаут — 10 секунд. Удержание и небольшое дрожание не создают новых повторений.

Краткий сбой приостанавливает движение, не создавая новых доказательств. До определения ритма окно восстановления равно пяти интервалам обработки + 80 мс с границами 250–600 мс. После появления ритма оно ограничивается 65% медианного периода (минимум 120 мс), чтобы не склеивать несколько быстрых хлопков. При возвращении проверяется согласованность центров кистей, включая перестановку порядка рук в ответе модели. После короткого пропуска или коррекции трекера незавершённый цикл полностью отбрасывается. Масштаб, которому не более 600 мс, можно повторно использовать после двух новых наблюдений разведённых кистей: остановка рук для такой подготовки не требуется. Старые близость и фаза не восстанавливаются. После длительной потери старые фаза и масштаб отбрасываются. Повторная подготовка принимает два новых наблюдения разведённых полных ладоней в окне до 220 мс с промежутком минимум 25 мс, согласованным размером (изменение до 22%) и правдоподобным смещением. Расстояние между ладонями может меняться: останавливаться в крайнем положении не требуется. Возвращение только готовит новый цикл, само не добавляет хлопок. После явной паузы, сброса или смены камеры/режима нужна обычная начальная подготовка. Близкое положение должно действительно наблюдаться до или после краткого сбоя. Само исчезновение руки никогда не подтверждает хлопок; скрытые циклы не восстанавливаются по предполагаемому ритму. Длительная потеря, несогласованная траектория, пауза и смена режима требуют нового исходного положения.

Качество проверяется по полноте/конечности точек и продольной длине ладони. Частично обрезанная ладонь может продолжать подготовленный цикл, если центр остаётся в изображении, видны минимум три из пяти опорных точек, в том числе запястье или средняя MCP, а остальные опорные точки выходят не более чем на 8%. Полностью ушедшая кисть отклоняется. Масштаб по частично видимым ладоням не калибруется. Текущая проекционная ширина не используется для отбраковки поворота ребром и не меняет нормализацию внутри цикла.

Углы/расстояния вычисляются после умножения нормализованных x/y на реальную ширину/высоту видео: прямоугольный кадр не искажает геометрию. EMA использует время (65 мс для приседаний, 12 мс для хлопков), а не количество кадров. Все выдержки, длительности циклов, пропуски и задержки заданы в миллисекундах. При длительной потере или невозможности восстановить траекторию незавершённый цикл сбрасывается; краткие пропуски только приостанавливают решение.

### Автоматический быстрый профиль хлопков

В режиме хлопков приложение проверяет 640×480 при 60 кадрах/с, затем 960×540 при 60 и 640×480 при 30. Запрашиваются только видео и выбранная камера. Возможности проверяются через применение ограничений и фактические `getSettings()`: диапазона `getCapabilities()` недостаточно для подтверждения сочетания частоты и разрешения. Если точные ограничения недоступны, сохраняется работающий режим браузера. Показаны отдельно выбранные настройки и фактически доставляемые кадры. Chrome, освещение и сама камера могут ограничить частоту; приложение не обещает 60, когда получено 30. Для приседаний восстанавливается исходный профиль 1280×720/30 и прежний алгоритм Full/Lite.

Модель распознаёт кисти в одном Worker. Второй Worker отслеживает текстурные детали ладоней и запястий методом разреженного пирамидального Lucas–Kanade по свежим изображениям, до 60 кадров/с. Его изображение имеет длинную сторону 320 пикселей. Проверяются обратное соответствие, отличие яркости и согласованность движения нескольких точек. Счётчик получает этот единственный поток наблюдений; ответы модели отдельно не увеличивают его. Реальное изображение должно подтверждать сближение и разведение, исчезновение руки не становится хлопком. Недостаток деталей больше не отключает трекер: он продолжает поиск, а доступные ответы модели используются в общем потоке наблюдений. Уменьшение нагрузки может помочь на следующем безопасном промежутке. Резерв «Только модель» используется при технической ошибке Worker или недоступных API.

Для модели и трекера используется один снимок одного и того же видеокадра. Задержанный ответ нейросети привязывается к исходному времени и переносится через короткую историю кадров к текущему изображению. Слишком старые ответы отклоняются. Числовые наблюдения для счётчика удерживаются в ограниченном окне около 110 мс (не более 12 записей): запоздавшее настоящее распознавание двух кистей может заменить только пропущенное наблюдение своего кадра, пока оно ещё не передано алгоритму. Уже обработанные кадры не переписываются. Это не очередь обработки изображений; трекер всегда обрабатывает только свежий кадр. Точки рисуются сразу, без этой задержки. В диагностике указаны задержка и источник наблюдения. Предсказанная скорость служит только начальным приближением поиска пикселей и не создаёт повторения. Возраст нейросетевой опоры ограничен 800 мс, разрыв между изображениями — 105 мс; потерянные наблюдения не восстанавливаются по предполагаемому ритму. Короткая история серых кадров существует только в оперативной памяти Worker для вычислений, не записывается на диск, не входит в диагностику и не передаётся по сети.

Частота модели подбирается в пределах 6–20 обработок/с по 95-му процентилю времени с кистями и бюджету 65% времени; кадры сравнения CPU/GPU исключены. Модель с временем 55 мс работает примерно 12 раз/с, а независимый трекер может обработать больше свежих кадров. Нагрузка и качество измеряются во время движения. При длительной нагрузке или устойчивом несовпадении «модель видит две кисти, оптических опор почти нет» трекер уменьшается до 256 пикселей; если этого недостаточно, камера переводится на 30 кадров/с. Изменение применяется в первом безопасном промежутке после трёх плохих оценок с шагом две секунды и не чаще раза в 15 секунд. Уменьшение кадра трекера отбрасывает незавершённое движение и допускает повторную подготовку в движении без новой двухсекундной задержки. Пропадание кистей само по себе не является причиной снижать разрешение.

Расписание модели накапливает временные сроки: например, цель 9 обработок/с на камере 30 кадров/с не округляется до 7,5. При занятом Worker старые кадры пропускаются. Короткие пропуски до 200 мс между подтверждёнными наблюдениями не обнуляют подготовку; новая близость при этом не придумывается. Каждый кадр обрабатывается максимум один раз, в каждом Worker только один кадр в обработке; очередь устаревших изображений не накапливается. Для приседаний предел обработки остаётся 20 кадров/с. Наложение рисуется максимум около 30 раз/с, развёрнутая диагностика — 4 раза/с. Кнопки обслуживает основной поток. После паузы, сброса, смены режима/камеры/модели требуется новая исходная поза. Результаты предыдущих поколений игнорируются.

## Проверки

`npm test` запускает автоматические проверки алгоритмов, оптического трекера на изображениях, профилей камеры, управления сеансом и диагностики. Точное число и результаты текущей версии приведены в `VALIDATION.md`. Быстрые серии содержат по 10 непрерывных циклов при 1–6 хлопках/с, 20/30/60 обработанных кадрах/с и четырёх смещениях момента выборки; остановок на крайних точках нет. Проверены единичные и повторные циклы, неполные приседания, наклон, покачивания, старт сидя/с ладонями вместе, удержание и дрожание кистей, короткое/долгое перекрытие, потеря тела/кистей и возвращение, смена стороны, большие пропуски кадров, пауза/сброс/режимы, устаревшие ответы, пропорции изображения и нормализация. Камерные проверки проверяют audio:false, прекращение дорожек при смене/выключении и позднем ответе разрешения, сообщения ошибок.

Браузерные проверки и их ограничения описаны в `VALIDATION.md`. Генерируемая тестовая камера и синтетические точки **не заменяют реальные движения** человека на S23.

## Короткая проверка на Samsung S23

При хорошем освещении, устойчивом телефоне и выбранной модели Full:

1. Сделайте **10 приседаний**. Число должно увеличиваться только при возвращении вверх, результат 10. Затем 10 секунд стойте неподвижно и отдельно наклоните корпус с прямыми коленями — число прежнее.
2. В режиме хлопков сначала покажите разведённые ладони, затем сделайте по **10 хлопков** в медленном и привычном темпе, без фиксации на концах движения. Отдельно проверьте примерно 3, 5 и 6 хлопков/с, меньший размах и движение одной рукой. Для каждой серии сравните ожидаемую прибавку 10 с фактической. Удерживайте ладони вместе 5 секунд, затем разведите — удержание не должно добавлять лишние повторы.
3. Начните движение, выйдите из кадра/спрячьте кисть, затем вернитесь. Старый цикл не должен завершиться. Короткое перекрытие кистей проверьте отдельно; при сомнении система должна попросить новый развод.
4. Начните половину движения, нажмите «Пауза», «Продолжить». Повторите со «Сбросить» и переключением режимов. Старое движение не должно засчитываться; числа режимов сохраняются раздельно.
5. Сверните Chrome и вернитесь: ожидается «Пауза». Нажмите «Продолжить», подтвердите исходную позу. Переключите переднюю/заднюю камеру и поверните телефон: точки должны совпадать с изображением.
6. Нажмите «Выключить камеру»: индикатор использования камеры должен погаснуть. Повторите «Начать». Проверьте запрет/повторное разрешение камеры в Chrome.
7. Запишите фактические числа и частоту кадров в «Диагностика». Для хлопков сравните «Доставка камеры», «Быстрый трекер», частоту модели и источник движения. Достаточно скопировать весь отчёт кнопкой. Настройка Lite относится только к приседаниям.

Дистанции ориентировочные; подберите их так, чтобы нужные точки хорошо помещались в кадре. Визуальный алгоритм хлопков **не гарантирует физический контакт ладоней**. Сильный разворот/перекрытие кистей, плохой свет, свободная одежда, обрезанные стопы и очень быстрые движения могут приводить к пропускам. При обработке 10–12 кадров/с некоторые быстрые сближения могут вообще не наблюдаться даже без ошибок модели; изменение порогов не восстанавливает отсутствующие данные. Выбор GPU помогает только если он действительно быстрее. Частота и точность версии 1.4.1 при 5–6 хлопках/с на S23 требуют реальной проверки; 90% не гарантируются синтетическими тестами; прежние приседания владелец проверил дважды с результатом 10/10. Это оценка заданного движения, не медицинская оценка техники.

## Как передать ошибку

В версии **1.4.1** раскройте «Диагностика» → нажмите «Скопировать диагностику» и вставьте текст в чат с Codex. Кнопка готовит короткий JSON: в начале обязательно находятся разрешение, fps, время обработки, фактический CPU/GPU, результат их сравнения и причина резервного режима. Также включены фактическая доставка камеры, отдельная скорость трекера, настройки автопрофиля, возраст опор и причина резерва. `opticalValidFrames` и `modelRepairedFrames` разделяют пиксельные опоры и помощь модели; `lastGoodOptical` сохраняет последнее успешное собственное отслеживание, а `activeNeuralLimitFps` показывает текущий применяемый предел отдельно от настройки гибридного режима. Затем идут состояние, статистика последних кадров, последний участок с двумя кистями, три последние попытки и причины отказов. Поле «Отчёт для отправки в чат» всегда видно и содержит точно тот же текст. После нажатия он не обновляется сам, чтобы его можно было спокойно выделить.

Если Clipboard API заблокирован, выполняется резервная попытка копирования. Если и она недоступна, нажмите «Выделить отчёт целиком» или удерживайте текст → «Выделить всё» → «Копировать». Полный журнал со всеми 180 наблюдениями и 12 попытками доступен отдельно: «Подробный журнал» → «Скачать полный журнал». Не нужно вручную выбирать поля или копировать только последние события.

Сразу после неудачной серии скопируйте отчёт и укажите ожидаемое/фактическое число и примерный темп. Показатели последнего участка с двумя кистями сохраняются даже после их исчезновения, паузы и выключения камеры; возраст измерения указан явно. Скорость кадров без рук не выдаётся за скорость при распознавании двух кистей. Журнал хранится в памяти вкладки и не содержит видео, звука или изображений.


## Размещение

Статическая сборка находится в `dist/`. Она включает все модели и WASM. Размещение с текущей аудиторией выполняется через Sites с `.openai/hosting.json`; успешная публикация подтверждается ответом сервиса, а не придуманным адресом. Для другого хостинга загрузите **содержимое** `dist` на HTTPS-сайт, обеспечьте доступ ко всем `/assets/*`, корректный MIME `application/wasm` и разрешение `camera=(self)`. Не добавляйте политику, блокирующую Worker или локальную компиляцию WASM. Публичный доступ не требуется.

## Браузерные проверки 1.4.1

`tests/browser-fast.cjs` проверяет настоящий оптический Worker и счётчик на сгенерированном видеопотоке 60 кадров/с с движущимися текстурными участками и управляемыми ответами нейросети с задержкой 55 мс. Тест проверяет раздельную частоту потоков, быстрые серии, потерю изображения, паузу, сброс и остановку. Это не реальные аплодисменты и не оценка точности Hand Landmarker на S23.

`tests/browser-claps.cjs` запускает настоящий Hand Landmarker на публичной фотографии кистей, программно перемещаемых в тестовой камере; проверяет наложение и два движения разной длительности. `tests/browser-smoke.cjs` проверяет Full/Lite/Hand, разрешение камеры, HTTP-ошибку модели и повторную попытку, остановку дорожек, фон и размеры экрана. `tests/browser-rhythm.cjs` проверяет настоящий оптический Worker на намеренно нетекстурном потоке, управляемые ответы модели, отсутствие постоянного отключения, непрерывные серии и возобновление в движении после долгой потери. `tests/browser-diagnostics.cjs` проверяет настоящий Clipboard API, совпадение с полем, отказ/отсутствие API, ручное выделение и скачивание полного JSON.

Браузерные тесты требуют Playwright (`PLAYWRIGHT_MODULE`), Chromium (`CHROME_BIN`) и работающий preview (`TEST_URL`). После обновления на S23 убедитесь, что диагностика показывает **1.4.1**, затем выполните реальные серии выше.
