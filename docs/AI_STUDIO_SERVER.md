# API для Google AI Studio / Cloud Run · 2.5.1

Если `/api/state` открывает интерфейс, APK попадает в обработчик HTML вместо
API. Исходный Worker с привязкой D1 работает на Sites; сам по себе он не
запускает сервер Node в AI Studio. В этой версии добавлен `server/node.js`,
который запускает тот же API с SQLite и обслуживает интерфейс на одном порту.

## Обновление в AI Studio

1. Загрузите исправления из ветки `codex/build-android-apk` / PR #2.
   Если AI Studio синхронизирует только `main`, сначала объедините PR.
2. Нужен Node.js 22.13+; Dockerfile использует Node.js 24.
3. Установите зависимости: `npm ci`.
4. Для предпросмотра запускайте `npm run dev`. Это Node API и Vite вместе.
   Сервер слушает `0.0.0.0` и переменную `PORT` (по умолчанию 3000).
5. Для опубликованного контейнера выполните `npm run build`, затем `npm start`,
   либо используйте включённый Dockerfile (порт по умолчанию 8080).
6. Перезапустите / повторно опубликуйте приложение в AI Studio. Простая
   установка нового APK не меняет уже работающий облачный сервер.

Проверка опубликованного адреса:

- `/api/health` возвращает JSON с `ok: true` и версией `2.5.1`.
- `/api/state` без выбранного имени возвращает HTTP 401 и JSON с кодом
  `SIGN_IN_REQUIRED`. Это ожидаемое поведение; HTML здесь быть не должно.
- После «Быстрый старт (Гость)» создаётся профиль; обычная тренировка
  отправляет повторения, рейтинги и дуэли используют тот же API.

APK 2.5.1 по умолчанию использует присланный адрес:
`https://ais-dev-unwfcvynbcdvpumsvvws2k-220077059769.europe-west2.run.app/api`.
Если публикация выдаст другой адрес, укажите его в приложении в разделе
«Подключение к серверу». При смене сервера его очередь и раунды изолированы:
неподтверждённые данные другого сервера автоматически туда не отправляются.

## Хранение и тестовый вход

SQLite хранится в `.data/movement.sqlite`; путь можно задать через
`MOVEMENT_DB_PATH`. Миграции выполняются при старте однократно, в транзакциях.
Локальная база сохраняется между перезапусками процесса с тем же диском.

На Cloud Run диск контейнера временный. Для короткого теста установите
**максимум один экземпляр**, чтобы тестировщики работали с одной базой;
при замене экземпляра / новой публикации эти тестовые данные могут исчезнуть.
Для постоянного сервера нужен отдельный этап настройки устойчивого хранилища.
Публикация Node-версии не переносит существующие данные из Sites/D1.

Сохранён текущий вход по имени из AI Studio: это режим тестирования,
не парольная авторизация. Пользователь с тем же именем получает тот же
тестовый профиль. Не используйте реальные персональные данные или секреты.
Входящие заголовки идентичности Sites в Node отбрасываются.

Для исходного локального предпросмотра Sites оставлена команда
`npm run dev:sites`; публикация Sites продолжает использовать Worker и D1.
