# Досрочное завершение вызова · тестовая 2.5.3

При досрочном завершении попытки подтверждённые повторения входят в счёт
вызова. Из трёх попыток выбирается лучшая, их значения не суммируются.
Остановка расходует одну попытку. Пустая прерванная попытка не создаёт
результат; если у участника нет ни одного зачётного результата, вызов
остаётся «Не состоялось» по истечении срока.

Раньше `competitionView` выбирал только `completed`, поэтому счёт `aborted`
был сохранён в БД, но не отображался и не участвовал в итогах. Теперь
положительный подтверждённый счёт `aborted` учитывается обоими участниками
и в API v1, и на страницах API v2. Уже сохранённые положительные результаты
прерванных попыток становятся видны при обновлении соревнований. Изменять
сами раунды или переписывать базу для этого не требуется.

Раунд остаётся `aborted`. Для личной истории, рекордов и спортивного рейтинга
нужен прежний `completed` за полные 60 секунд. Распознавание, `squat-v1`,
модель, лимиты и дневные награды сохраняются. Дополнительных запросов к БД
при расчёте счёта вызова нет.

Перед `abort` клиент ждёт локальные записи и подтверждение всей очереди
повторений. При сетевой ошибке результат остаётся неподтверждённым, доступна
повторная отправка с прежними идентификаторами. Это сохраняет последние
повторения и исключает повторный расход попытки. Если приложение закрыто
или перезагружено до такой отправки, действует прежний режим восстановления:
события, доставленные уже после серверного прерывания, пополняют дневной
прогресс, а счёт вызова использует подтверждённый до остановки `round.count`.

## Проверки

- Воспроизведено прежнее поведение в двух браузерных профилях: дневные
  значения 2 и 1 сохранены, оба счёта вызова были `null`.
- Три новых серверных теста сначала воспроизвели ошибку, затем прошли:
  API v1/v2, оба участника, лучший результат, победа, ничья, три попытки,
  повторный `abort`, версия правил, отсутствие минутных рекордов и повторных
  дневных наград.
- В `browser-backend.mjs` добавлены два сценария: APK ждёт задержанное последнее
  повторение; после потери уже обработанного ответа повторное сохранение
  не меняет счёт и лимит. Оба участника видят 2:1, в том числе после
  перезапуска. Камера и HTTP-мост в этой проверке имитируются; используется
  настоящий API с изолированной SQLite.
- Полный локальный набор: 176 unit/integration-тестов; восемь целевых
  браузерных сценариев; typecheck, format:check, lint, build, backend:validate.
- [CI 39844211777](https://github.com/rojoscarlos-cpu/Test/actions/runs/39844211777):
  176 unit/integration-тестов, 47 браузерных сценариев, Android-сборка и staging
  прошли. Публичное скачивание проверено по полному SHA-256 файла; рабочий
  deploy пропущен.

## Проверка на телефонах

Обновить «Движение Тест UI» поверх установленного приложения. Создать или
открыть принятый вызов; каждому участнику выполнить несколько повторений
и нажать «Завершить досрочно». Дождаться подтверждения сохранения. Открыть
соревнования и обновить их на обоих устройствах: должны отображаться
лучшие счёты. Проверить повторное открытие приложения и следующую попытку.
Дневной прогресс должен увеличиться, а рекорд за минуту — сохраниться.

Работа ведётся только в `codex/server-optimization` и тестовом Worker/D1
`movement-test-api-staging`. Слияние в `main` и рабочая публикация не выполняются.
