# Node API для локального / AI Studio предпросмотра

Основной репозиторий — `APP-updated-version-`, ветка `main`, версия 2.5.4. Единственный облачный сервер работает на Cloudflare Workers + D1. Node API нужен для локального предпросмотра и не заменяет постоянную D1: [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md).

## Запуск

1. Получить актуальные исходники main нового репозитория; изменения делать в отдельной ветке.
2. Использовать Node.js 24+, выполнить `npm ci`.
3. Для разработки запустить `npm run dev`: Node API и Vite на `PORT` (по умолчанию 3000).
4. Для готовой сборки выполнить `npm run build`, затем `npm start`. Dockerfile использует Node.js 24 и порт 8080 по умолчанию.

`GET /api/health` возвращает JSON с текущей версией. До гостевого входа `/api/state` отвечает `401 DEVICE_AUTH_REQUIRED`. HTML на этом маршруте означает ошибку маршрутизации API. Текущая авторизация — индивидуальная сессия устройства, не вход по отображаемому имени. Заголовки идентичности Sites в Node отбрасываются.

SQLite по умолчанию хранится в `.data/movement.sqlite`; путь задаётся `MOVEMENT_DB_PATH`. Миграции применяются при старте. Данные сохраняются при перезапуске с тем же диском.

В Cloud Run диск контейнера временный. Для краткого предпросмотра можно использовать один экземпляр; после его замены данные могут исчезнуть. Для постоянных пользователей используется существующая Cloudflare D1. Публикация Node-предпросмотра не переносит данные из D1 или Sites.

Текущий APK использует единственный основной Cloudflare Worker с сохранённым техническим именем movement-test-api-staging. Адрес подключения можно посмотреть в общей диагностике. Смена сервера изолирует профиль, очередь и раунды; неподтверждённые данные другого сервера туда автоматически не отправляются.

Сохранение исходников запускает CI, но не публикацию серверов. Рабочий deploy и слияние — только по прямой команде владельца. [Разработка и CI](DEVELOPMENT.md).
