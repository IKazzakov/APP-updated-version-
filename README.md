# Движение · Счётчик приседаний

MVP существующего `exercise-counter`: одно упражнение — приседания без дополнительного веса. Интерфейс на русском, рассчитан на вертикальный Chrome на Samsung Galaxy S23 и настольный Chrome. Существующие численные пороги распознавания приседаний сохранены. Хлопки, их модель, трекеры и переключатель упражнения удалены.

## Исправления APK и AI Studio · 2.5.1

Камера и счётчик обычного подхода доступны даже без серверного профиля:
на экране явно указано, что такой тест не сохраняется. Минутные раунды и
дуэли требуют подключения. Android-сборка использует присланный владельцем
адрес `ais-dev-…run.app`, показывает HTTP-код проверки и позволяет изменить
HTTPS-адрес в разделе «Подключение к серверу» без пересборки.

Для AI Studio добавлен Node API с SQLite: `npm run dev` запускает API и Vite,
`npm run build && npm start` — готовый клиент и API. Dockerfile использует
Node.js 24. Обновление серверной части обязательно, если `/api/state`
возвращает HTML. Инструкция и ограничения тестовой базы Cloud Run:
[docs/AI_STUDIO_SERVER.md](docs/AI_STUDIO_SERVER.md).

## Открыть приложение

Действующий адрес проекта: https://exercise-counter.stonypony5.chatgpt.site

Приложение приватное: доступ задаётся в Sites, вход выполняется через ChatGPT. Для проверки со вторым человеком владелец сначала открывает **«Поделиться» / настройки доступа Sites** и добавляет друга. После этого отправляет ему отдельную ссылку соревнования из приложения. Ссылка соревнования сама по себе не открывает доступ к приватному сайту. Не передавайте ключи или токены в чат.

При первом входе создаётся профиль с именем «Участник». Нажмите имя вверху и задайте своё имя для соревнований. Часовой пояс определяется устройством только при создании профиля и сохраняется на сервере. Следующие устройства используют тот же пояс.

Если встроенный предпросмотр ограничивает камеру, откройте прямой адрес отдельной вкладкой Chrome. Нужен HTTPS или `localhost`; доступ к микрофону не запрашивается.

## Четыре раздела

- **Сегодня:** задание — 10 засчитанных приседаний без ограничения времени, за несколько подходов. Приседания из всех режимов суммируются. Первое выполнение за календарный день даёт 10 баллов, дополнительные повторения баллов не добавляют. Пропуски не отнимают баллы. Здесь же календарь и число выполненных дней за последние 7 дней.
- **Тренировка:** обычные подходы с паузой либо «Мой результат за 60 секунд». Сброс текущего подхода не удаляет сохранённый дневной прогресс и историю.
- **Соревнования:** заочный вызов одному другу. После принятия — 24 часа, каждому максимум три минутные попытки. Побеждает лучший завершённый результат. До принятия попытки недоступны. Прерванная попытка расходуется, но её результат не участвует в сравнении. Равенство — ничья; без завершённого результата хотя бы одного участника — «Не состоялось». До завершения итоги предварительные.
- **Мой прогресс:** последний и предыдущий сопоставимые минутные результаты, разница, рекорд, график и история. Первый раунд — исходная точка без вымышленного сравнения. Обычные тренировки и прерванные минуты исключены.

Дуэли, рейтинг минутного результата, баллы и личный прогресс независимы. Баллы не определяют победителя дуэли или спортивное место.

## Недельные рейтинги и бонусы · 2.2.0

В **«Соревнованиях»** три внутренние вкладки: «Дуэли», «Результат», «Баллы». Четыре основных раздела сохранены. Начиная с 2.3.0 все существующие и новые пользователи участвуют по умолчанию. В профиле есть **«Не участвовать в общих рейтингах»**: установленная галочка и сохранение профиля скрывают пользователя. Другим пользователям с доступом к APP видны выбранное имя, результат и баллы. Сохранённый после этого отказ не сбрасывается повторным входом или развёртыванием. Почта, идентификатор входа, личные раунды и приглашения в таблицы не передаются. Отключение скрывает строки и сохраняет баллы; исторические спортивные места остальных не пересчитываются.

- **Результат:** один лучший положительный завершённый личный раунд или попытка дуэли ровно за 60 секунд. Версия `squat-v1` явно закреплена в записи недели; другие версии не смешиваются. Неделя определяется по серверному `ends_at` в **Africa/Johannesburg (UTC+2)**, с понедельника 00:00 до следующего понедельника, правая граница исключена. До закрытия места предварительные, затем сохраняется неизменяемый итог. Равенство даёт места 1, 1, 3 или 1, 2, 2, 4. Награды: +20 / +10 / +5 за первое / второе / третье; каждый разделивший место получает всю награду. Участие фиксируется при серверном закрытии.
- **Баллы:** сумма исходных `daily_rewards` (+10 за день) и отдельного журнала недельных бонусов. Неделя / всё время, без награды за место по баллам. Участвующие с нулевым балансом также видны. Старые дневные баллы включаются в общий баланс один раз.
- **Полная неделя:** +20 за семь различных выполненных дат Пн–Вс из `daily_rewards.local_date` в неизменяемом поясе профиля, независимо от участия в рейтингах. Это не скользящий `last7`. Пять дней = 50; семь = 90; семь и первое спортивное место = 110.

«Твоя неделя» показывает календарную неделю профиля, семь отметок, возможность бонуса и расшифровку баллов. «Последние 7 дней» остаётся отдельным скользящим показателем. «Мои места за неделю» использует общую спортивную неделю UTC+2; около понедельника эти периоды могут отличаться. В «Моём прогрессе» доступна история недель. Подтверждение просмотра итогов хранится на сервере и сохраняется между устройствами. Позднее увеличение суммы отмечается в истории без повторного автоматического показа просмотренной карточки. Итоги не перекрывают камеру.

**Закрытие и задержки.** Сервер закрывает спортивную неделю строго после её конца + 15 секунд сетевой доставки, предварительно прерывая истёкшие активные раунды. Снимок мест, награды и закрытие выполняются одной D1-транзакцией, уникальные ключи исключают повторное начисление. Момент finish не переносит раунд в другую неделю. После закрытия спортивные награды не пересчитываются при открытии страницы.

События дневного задания по-прежнему можно доставить за 7 дней. Позднее выполнение исходной даты может добавить её +10 и восстановить +20 полной недели — в исходную неделю. Сводки и рейтинг баллов обновляются, спортивный итог сохраняется. Пока возможна такая доставка, интерфейс предупреждает, что баллы могут дополниться (консервативный запас учитывает разные пояса профилей). Недельная активация записывается один раз на первом серверном обращении; существующие данные этой недели включаются. Бонусы за более ранние недели автоматически не выдаются.

Обработка идемпотентна и выполняется сервером при API-запросах, для всех пользователей и всех пропущенных периодов после активации. Открытый браузер в момент границы не нужен; отдельный планировщик и платные сервисы не подключались. После длительного отсутствия итог станет виден на следующем обращении.

## Камера и одинаковые правила

Поставьте телефон устойчиво в 2–3 метрах, примерно на высоте таза. Встаньте боком или под небольшим углом; таз, колени и стопы должны целиком помещаться в кадре. Освещение должно позволять различить тело. Подготовка включает загрузку модели и подтверждение положения стоя. Изображение передней камеры зеркальное; точки тела зеркалятся вместе с ним.

Используется только **MediaPipe Tasks Vision 0.10.32, Pose Landmarker Full**. Модель, Worker и совместимые WASM размещаются с приложением; сторонний CDN для распознавания не требуется. Видеокадры обрабатываются последовательно в Worker без очереди устаревших кадров; кнопки остаются доступны.

Правила `squat-v1` находятся в `src/config.js`, серверная версия — в `server/rules.js`. Один и тот же `SquatCounter` используется во всех режимах:

1. Устойчивое положение стоя: угол колена ≥160°, подтверждение 650 мс.
2. Опускание начинается при угле <145°.
3. Нижнее положение требует одновременно угол ≤108° и снижение нормированной высоты таза минимум на 0,16, подтверждение 90 мс.
4. Возврат: угол ≥160° и остаточное снижение <0,09, подтверждение 120 мс. Только тогда добавляется повторение; минимальный цикл — 650 мс.

Углы вычисляются в пиксельных координатах с учётом пропорций изображения. Высота нормируется длиной ноги. Используется лучше видимая сторона, шум сглаживается по времени. Наклон корпуса с прямыми коленями не удовлетворяет обоим условиям. Покачивания внизу не создают отдельные повторения. Потеря наблюдения, смена стороны, пауза или сброс отбрасывают незавершённый цикл; после возвращения требуется исходное положение. Приложение оценивает заданное движение и не даёт медицинской оценки техники.

В минутном режиме пользователь нажимает **«Подготовиться»** и отходит от телефона. После двух секунд устойчивого исходного положения автоматически идёт **5–4–3–2–1**, после чего сервер открывает 60-секундное окно. Подготовка в минуту не входит. Других нажатий для запуска не нужно. Устойчивость оценивается по существующей видимости тела и прямым коленям, без требования абсолютной неподвижности. Короткие пропуски до 220 мс фильтруются, длительная потеря положения отменяет отсчёт и требует нового подтверждения. Во время ожидания и отсчёта доступна «Отменить»; попытка соревнования ещё не израсходована. После конца новая попытка требует нового нажатия «Подготовиться». Таймер использует монотонное время и не зависит от числа кадров. Потеря тела не останавливает время. Засчитываются только полные циклы внутри окна; поздние результаты обработки не продлевают минуту. Пауза недоступна. Досрочное завершение, уход в фон, перезагрузка и выключение камеры прерывают попытку. Подтверждённые приседания из неё остаются в дневном задании.

## Данные и сервер

Используются встроенные **авторизация Sites / ChatGPT** и **Cloudflare D1, binding `DB`**. Отдельные платные сервисы, внешняя авторизация и секретные ключи не требуются. Существующий Sites `project_id` сохранён. До MVP серверной истории и базы в проекте не было; прежний счётчик жил только в памяти вкладки. Исходная миграция MVP сохранена. Новая добавочная миграция `0001_weekly_rankings.sql` расширяет профиль и создаёт недельные таблицы; история, дневные награды и прежние баллы не удаляются.

Телефон определяет движения по видео. На сервер передаются только идентификаторы событий, число повторений через отдельные события, время события и при необходимости идентификатор/прошедшее время раунда. **Изображения, видео, звук и координаты тела не записываются и не отправляются.**

Сервер проверяет вход, принадлежность истории, участников соревнования, часовой пояс и границы дней, сроки, лимит трёх попыток, единственный активный минутный раунд, версии правил, идемпотентность и однократные награды. События и награда фиксируются одной транзакцией с уникальными ключами. Сервер не доказывает физическое выполнение упражнения: это дружеский формат.

Неподтверждённые события хранятся на устройстве в IndexedDB и повторно отправляются с теми же UUID. Две вкладки и сетевые повторы не дублируют награды. Камеру для подсчёта может использовать только одна вкладка приложения: это проверяется встроенной блокировкой Chrome. Интерфейс не называет прогресс сохранённым до подтверждения сервера. Обычные события можно доставить с задержкой до 7 дней; дата берётся из времени события в поясе профиля. Для минутного результата есть до 15 секунд на доставку после таймера, без продления упражнения. Затем неподтверждённая попытка становится прерванной. Не очищайте данные браузера, пока есть ожидающие отправки повторения.

Доступ к личной истории ограничен текущим профилем. Соревнование видят только его участники. Получателю приглашения до принятия показываются только имя автора, версия правил и доступность приглашения. В БД хранится хеш случайного токена; сама ссылка передаётся во фрагменте адреса. Подробный API: [docs/API.md](docs/API.md).

## Локальный запуск

Нужны Node.js **24+** и npm. Зависимости закреплены в `package-lock.json`.

```sh
npm ci
npm test
npm run build
npm run db:migrate:local
npm run dev:sites
```

При ограничениях файловой системы npm можно указать доступный кеш: `npm ci --cache /tmp/exercise-npm`. Preview и локальная база не содержат реальные production-данные. Локальная авторизация инструмента разработки не является production-профилем. Для проверки именно размещённого входа используйте приватный Sites.

Для просмотра готовой сборки: `npm run preview`. Для телефона через локальную сеть требуется отдельный HTTPS-адрес; `http://IP-компьютера` не обеспечивает доступ к камере. Доступный в текущем окружении инструмент предпросмотра не обязательно доступен самому телефону.

## Структура и размещение

- `src/camera.js`, `models.js`, `vision.worker.js`, `overlay.js` — камера, модель и точки тела.
- `src/algorithms/squat.js`, `session.js`, `training.js`, `round-clock.js`, `config.js` — общий подсчёт, управление и таймер.
- `src/main.js`, `style.css`, `progress.js`, `weekly.js` — четыре раздела интерфейса и личные сравнения.
- `src/api.js`, `outbox.js` — серверные запросы и надёжная отправка.
- `src/diagnostics.js`, `clipboard.js` — безопасный диагностический отчёт и ручное копирование.
- `server/api.js`, `rules.js`, `weeks.js`, `worker.js` — серверные правила, авторизация и ресурсы.
- `drizzle/` — добавочные SQL-миграции D1; применённые миграции не редактировать.
- `tests/` — автоматические проверки; тестовые личности/базы отделены от приложения.
- `.openai/hosting.json`, `vite.config.js` — существующий Sites и официальный плагин сборки.

`npm run build` проверяет SHA-256 модели, копирует WASM из того же npm-пакета, собирает `dist/client` и `dist/server`, упаковывает конфигурацию и SQL-миграции Sites. Публикация выполняется через Sites из сохранённой и отправленной исходной версии; платформа подключает `DB` и применяет миграции. Не меняйте приватную аудиторию на публичную для обхода ошибки доступа.

## Диагностика и ограничения

В разделе «Тренировка» раскройте «Диагностика» и нажмите **«Скопировать диагностику»**. Вставьте текст в чат и опишите действия и ожидаемое/полученное число повторений. Если копирование заблокировано, выделите текст отчёта под кнопкой и скопируйте вручную. Не присылайте видео, ссылки-приглашения или токены.

Отчёт содержит только версии приложения/правил, браузер, технические состояния камеры и модели, режим, приблизительную скорость и коды ошибок. Имён, профилей, ссылок, токенов и координат в нём нет.

Распознавание зависит от ракурса, освещения, видимости ног и производительности телефона. Синтетические проверки не заменяют физическое выполнение. Актуальные выполненные проверки и сценарий для Samsung S23 — в [VALIDATION.md](VALIDATION.md). Защита от умышленной подмены клиентских результатов в MVP не заявляется.

## Повторить браузерные проверки

Нужны Chromium и Playwright Core (в рабочей среде уже установлены). Пути можно задать через `CHROMIUM_PATH`; для теста MVP при необходимости установите Playwright Core локально в окружение тестирования.

- Соберите приложение. В отдельном терминале: `node tests/browser-server.mjs` — только loopback, отдельная SQLite в памяти, три фиксированных тестовых профиля. Затем `npm run test:browser`. Тесты используют синтетические положения и управляемое время; к размещённой базе не обращаются. `TEST_ORIGIN` меняет адрес тестового сервера.
- Для настоящей загрузки модели запустите мигрированный dev-предпросмотр на порту 4177: `npm run dev:sites -- --port 4177`. Затем `npm run test:browser:model`. Можно указать `MODEL_TEST_ORIGIN`. Это проверка Full/WASM на искусственном видео Chromium, а не точности реального движения.

Данные локальной разработки и отчёты находятся в игнорируемых `.wrangler/` и `test-results/`. Тестовые маршруты и личности не включаются в production Worker.

## Звук минутного раунда (2.1.0)

Нажатие «Подготовиться» активирует Web Audio в том же пользовательском действии, до ожидания разрешения камеры. «Звук» отключает сигналы; «Проверить сигнал» позволяет проверить громкость до отхода от телефона. Различаются положение определено, каждый шаг отсчёта, старт и окончание. Всё генерируется локально, микрофон не нужен. Старт звучит только после подтверждения сервера. При отказе браузера показывается сообщение; крупные визуальные подсказки сохраняются. Состояние AudioContext не доказывает, что физический динамик включён или звук достаточно громкий — проверьте сигнал на телефоне.

При отмене уже отправленного запроса запуска сервер мог успеть открыть минуту: тогда она прерывается и считается использованной. Обычная отмена ожидания или отсчёта не отправляет запрос запуска и не расходует попытку.

Дополнительные проверки: `node tests/browser-auto-start.mjs` с локальным `tests/browser-server.mjs`.

### Исправление запуска 2.1.1

После окончания 5–4–3–2–1 готовность фиксируется **до** запроса запуска. Пока сервер отвечает, движение человека и пропуск кадров не отменяют запрос. После подтверждения запускается таймер; если поза потеряна, для повторений требуется новое исходное положение стоя. Предыдущий незавершённый цикл не переносится. Явная отмена, выключение камеры и уход в фон по-прежнему прерывают запуск.

Ответ запуска содержит фактическое серверное время и длительность обработки; клиент отделяет её от сетевой задержки при согласовании таймера. В диагностике `startEvents` хранит только этапы запроса и длительность, без идентификаторов или личных данных. Ошибка подтверждения дублируется возле камеры.

Для новых интерфейсов после сборки и запуска изолированного `tests/browser-server.mjs`: `npm run test:browser:weekly`. Эта проверка использует только тестовые профили и тестовое время, не production-таблицы.

## Исправления 2.3.0

Рейтинг больше не очищается при каждом уведомлении очереди и обновлении общего состояния. Открытие вкладки, смена периода и «Обновить» загружают данные; содержательное изменение своих результатов/баллов или настроек обновляет таблицу без очистки. Одинаковые параллельные запросы объединяются, поздний ответ предыдущей вкладки игнорируется. При ошибке обновления уже показанные строки остаются с явной подписью, что это предыдущие данные.

Автор непринятого приглашения может нажать **«Отменить вызов»** рядом со ссылкой или в карточке дуэли. Отменённое приглашение остаётся в истории, ссылка становится недействительной, попытки не расходуются. Принятые дуэли отменить нельзя. Сервер атомарно разрешает только одно из конкурирующих действий: принять или отменить.

Добавочная `0002_ranking_defaults_duel_cancel.sql` включает участие по умолчанию для всех через новый постоянный флаг отказа `rankings_excluded=0`, не переписывая старые миграции и не сбрасывая данные. Старый `rankings_enabled` сохранён как исторический столбец, но больше не определяет участие. Новые отказы записываются в rankings_excluded и сохраняются между устройствами. Уже закрытые спортивные итоги и награды не пересчитываются.

Проверка регрессий: `npm run test:browser:fixes` после запуска отдельного `tests/browser-server.mjs`. Реальные данные сайта тесты не используют.

## Android MVP и PWA · 2.4.0

В версии 2.4.0 добавлена полная поддержка тестирования приложения на смартфонах Android как через браузер, так и в виде установленного на экран PWA-приложения:

1. **Screen Wake Lock API:** во время обычной тренировки, фазы подготовки (5–4–3–2–1) и 60-секундного раунда экран смартфона автоматически удерживается включённым (`navigator.wakeLock`). Он не затухает, когда спортсмен отходит на 2–3 метра от устройства.
2. **Аппаратное GPU-ускорение (MediaPipe):** в `vision.worker.js` инференс позы по умолчанию запускается через WebGL/GPU-делегат, что обеспечивает стабильные 30 FPS на смартфонах без перегрева процессора. Если устройство не поддерживает GPU-делегат в воркере, происходит автоматический откат на CPU.
3. **PWA-манифест и Service Worker:** добавлены `manifest.webmanifest` и `sw.js` с режимом `display: standalone`, благодаря чему на Android приложение запускается на весь экран без адресной строки и вкладок браузера («Добавить на главный экран»).
4. **Быстрый старт (Гость):** добавлена кнопка мгновенного входа в один тап (`⚡ Быстрый старт (Гость)`), позволяющая мгновенно начать тестирование без ввода имени с клавиатуры.
## Сборка Android APK (Capacitor) · 2.5.0

В версии 2.5.0 добавлена полная поддержка сборки автономного Android APK через Capacitor:

1. **Нативная платформа Android (`android/`):**
   - Настроена конфигурация `capacitor.config.json` с идентификатором `com.movement.squat` и заголовком «Движение».
   - В `AndroidManifest.xml` прописаны разрешения камеры (`android.permission.CAMERA`), доступа в сеть (`android.permission.INTERNET`) и удержания экрана включённым (`android.permission.WAKE_LOCK`).
   - Установлена принудительная вертикальная ориентация `android:screenOrientation="portrait"` для стабильного распознавания приседаний на Samsung Galaxy S23.
2. **Маршрутизация сетевых запросов в APK:**
   - В `src/api.js` добавлена автоматическая маршрутизация: при запуске внутри нативного WebView Capacitor сетевые запросы отправляются на публичный сервер приложения.
3. **Команды синхронизации и сборки:**
   - `npm ci`: устанавливает закреплённые зависимости из `package-lock.json`.
   - Нужны полный JDK 21, Android SDK 36 и Build Tools 36.0.0. Задайте `JAVA_HOME` и `ANDROID_HOME`; лицензии SDK должны быть приняты.
   - `npm run build:android`: собирает веб-ресурсы, готовит отдельную папку `dist/android-client` без APK/архивов исходников и синхронизирует Capacitor; APK эта команда не компилирует.
   - `npm run build:apk`: собирает веб-клиент, синхронизирует Capacitor, запускает Gradle, проверяет подпись/версию/ресурсы и сохраняет готовый `work/artifacts/app-debug.apk`.
   - Копии создаются в `public/app-debug.apk` и `dist/client/app-debug.apk` для кнопки скачивания. Рядом находится SHA-256. Предыдущий APK не включается внутрь новой сборки.
   - Версия Android автоматически берётся из `package.json`: для 2.5.0 это `versionName=2.5.0`, `versionCode=20500`.

Нативные запросы выполняются через `CapacitorHttp`, с cookie-хранилищем Android и Origin публичного API. Это устраняет блокировку WebView CORS и отклонение POST сервером. Адрес по умолчанию в 2.5.1 исправлен на `ais-dev`; изменить его можно в APK или задать `VITE_API_BASE_URL=https://ваш-сервер/api` перед сборкой. В браузере запросы остаются относительными `/api`. Приглашения из APK используют публичный адрес, а не `https://localhost`. Service Worker в APK не регистрируется. Во время тренировки экран удерживает нативный плагин `WorkoutScreen`, без зависимости от поддержки Web Wake Lock в WebView.

Инструкция тестировщику и ограничения debug-сборки: [docs/ANDROID_TESTING.md](docs/ANDROID_TESTING.md).
