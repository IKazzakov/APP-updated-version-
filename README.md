# Движение · Счётчик приседаний

Основной репозиторий: [rojoscarlos-cpu/APP-updated-version-](https://github.com/rojoscarlos-cpu/APP-updated-version-). Основная ветка — `main`, текущая версия — **2.5.3**. Изменения разрабатываются в отдельных ветках и проходят PR. Слияние и публикация рабочего сервера выполняются по прямой команде владельца.

Приложение считает приседания через камеру. Видео обрабатывается на устройстве: MediaPipe Pose Landmarker Full, модель и WASM включены в приложение. На сервер отправляются события повторений, без видео, звука или координат тела. Алгоритм `squat-v1` общий для всех режимов; параметры находятся в `src/config.js`.

## Начать пользоваться

1. При первом открытии нажать **Быстрый старт (Гость)** либо ввести имя и нажать **Начать**. Ответ `401 DEVICE_AUTH_REQUIRED` до этого — ожидаемое требование входа.
2. Открыть **Тренировка → Начать** и разрешить камеру. Микрофон не запрашивается.
3. Дождаться подтверждения сохранения перед выходом или очисткой данных приложения.

Четыре раздела: «Сегодня», «Тренировка», «Соревнования», «Мой прогресс». Профиль доступен из шапки. Общая диагностика и настройка подключения находятся внизу всех экранов.

Дневное задание — 10 повторений; первое выполнение за календарный день даёт +10 баллов. Полная календарная неделя профиля даёт +20. Спортивный рейтинг использует лучший положительный результат полной минуты `completed`, спортивную неделю Africa/Johannesburg и версию правил. Места и баллы рассчитывает сервер.

В вызове каждому доступны три попытки за 24 часа после принятия. Сравнивается лучший результат. Положительные подтверждённые повторения досрочно остановленной попытки учитываются у обоих участников, но раунд остаётся `aborted` и не даёт минутный рекорд. До завершения клиент сохраняет события локально и ждёт подтверждения очереди с устойчивыми UUID. Подробные правила: [API](docs/API.md), [досрочное завершение](docs/DUEL_EARLY_STOP.md).

## Разработка и проверки

Нужны Node.js 24+ и npm. Зависимости закреплены в `package-lock.json`.

```sh
npm ci
npm run typecheck
npm run format:check
npm run lint
npm test
npm run build
npm run backend:validate
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser:all
```

Для браузерных сценариев нужен `playwright-core@1.58.2`, доступный через `NODE_PATH`, и Chromium/Chrome. Проверки используют отдельные SQLite, тестовые профили и искусственную камеру. Базовый набор — 176 unit/integration-тестов и 47 браузерных сценариев. Он не заменяет проверку настоящей камеры и производительности Galaxy S23.

`npm run dev` запускает Node API, локальную SQLite и Vite. `npm run dev:sites` оставлен для локального Sites-предпросмотра. Для камеры требуется HTTPS или localhost. Размещённый Sites и его аудитория не изменяются при работе с репозиторием.

Android: полный JDK 21, SDK 36, Build Tools 36.0.0 и постоянный ключ. После подготовки путей:

```sh
source scripts/android-env.sh
npm run build:apk:staging
```

Результат — `work/artifacts/app-debug.apk` с метаданными и SHA-256. Имя команды `staging` сохранено для совместимости существующего пакета и его ключа. Для этого установленного приложения не использовать обычный `build:apk`: он следует базовой конфигурации другого пакета.

## CI и публикация

Push в любую ветку и PR в `main` запускают проверки. После успешного push в `main` собирается APK с постоянным ключом; его можно скачать из Actions artifacts. Ручной запуск **Movement — checks and APK** с `build_apk=true` позволяет проверить APK отдельной ветки. Workflow не создаёт коммиты и не выполняет слияние.

Публикация выполняется отдельно через **Movement — manual deployment**: явный выбор `staging`/`production` и соответствующее подтверждение. Production разрешён только из `main`. Push и PR не публикуют серверы. Секреты нового репозитория настраиваются отдельно; старые отчёты не подтверждают их наличие.
