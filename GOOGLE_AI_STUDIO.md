# Работа с проектом в Google AI Studio

Текущий проект `Test` приведён к версии APP **2.3.0** из
`rojoscarlos-cpu/exercise-counter`, ветка `main`, коммит
`291e65657ef77a9bbb461a90b908c9dbb8a611eb`.
Исходные файлы этой версии перенесены без изменений; метаданные AI Studio
обновлены, файлы прежнего режима хлопков удалены.

## Что входит в версию

- «Сегодня»: 10 приседаний, дневные баллы и календарь.
- «Тренировка»: обычный подход и результат за 60 секунд, подготовка,
  автоматический отсчёт и звуковые сигналы.
- «Соревнования»: дуэли с другом, недельные рейтинги результата и баллов,
  возможность отменить непринятый вызов.
- «Мой прогресс»: история, сравнение минутных результатов и недельные итоги.
- Серверное сохранение, повторная отправка событий через IndexedDB,
  защита от повторных начислений и одновременного использования камеры.

## Редактирование и запуск

Google AI Studio можно продолжать использовать для редактирования исходников.
После импорта архива сохраняйте структуру `src/`, `server/`, `drizzle/`,
`public/`, `scripts/`, `.openai/`, а также `package.json`, `package-lock.json`
и `vite.config.js`. Не заменяйте проект новым React-шаблоном.

Нужны Node.js 24+ и npm:

```sh
npm ci
npm test
npm run build
npm run db:migrate:local
npm run dev -- --host 0.0.0.0 --port 3000
```

Локальные миграции создают только базу разработки. Вход в разработке
предоставляет Sites Vite plugin; это отдельный тестовый профиль.
Видео обрабатывается на устройстве; сервер получает события повторений.
Для камеры нужен HTTPS или localhost. Localhost удалённого окружения
не является адресом, доступным с телефона.

## Сервер и публикация

APP 2.3.0 использует Cloudflare Worker, D1 (`DB`) и вход Sites / ChatGPT.
Обычная статическая публикация или один клиентский `index.html` не обеспечат
историю, дуэли и рейтинги. Для размещения на другом сервере потребуется
совместимая реализация авторизации, API и хранилища; она не входит в перенос.

В `.openai/hosting.json` сохранён идентификатор существующего APP.
Для обновления APP используйте его текущий процесс публикации Sites.
Для отдельного размещения Test потребуется отдельная конфигурация проекта.
Перенос файлов сам по себе не публикует сайт и не изменяет размещённую базу.

Миграции `drizzle/0000`–`0002` переносите вместе с сервером. Уже применённые
миграции не переписывайте: новые изменения схемы добавляйте отдельным файлом.
Контракт API описан в `docs/API.md`.

## Проверки после изменения

`npm test` проверяет алгоритм, управление тренировкой, сервер и недельные
начисления. `npm run build` проверяет комплектность клиентской и серверной
сборок, модели и SQL-миграций.

Для браузерных тестов нужен `playwright-core` и Chromium. Запустите
`node tests/browser-server.mjs` и по очереди выполняйте
`npm run test:browser`, `npm run test:browser:auto`,
`npm run test:browser:weekly`, `npm run test:browser:fixes`.
Они используют отдельную тестовую базу и синтетические движения.
`npm run test:browser:model` проверяет настоящую модель на dev-сервере;
его адрес задаётся через `MODEL_TEST_ORIGIN`.

Точность реальных приседаний, доступ к камере и слышимость сигналов
проверяйте отдельно на телефоне по сценарию из `VALIDATION.md`.
