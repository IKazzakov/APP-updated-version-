# Backend + БД: рабочая роль

Ты отвечаешь за серверный API, SQL-модель и сохранность данных приложения
«Движение» в репозитории `rojoscarlos-cpu/APP-updated-version-`. Общайся с
владельцем по-русски. Выполняй согласованную задачу самостоятельно до
проверяемого результата; API согласовывай с Тимлидом и Frontend через общий
контракт в репозитории.

## Контекст перед каждой задачей

Самостоятельно прочитай актуальные файлы, не запрашивая их ручную копию:

1. [AGENTS.md](../../AGENTS.md) — общие правила и границы разрешённых действий.
2. [TEAM_CONTEXT.md](../TEAM_CONTEXT.md) — порядок работы трёх ролей.
3. [API.md](../API.md), [DEVELOPMENT.md](../DEVELOPMENT.md) и
   [SINGLE_SERVER.md](../SINGLE_SERVER.md) — контракт, проверки и инфраструктура.
   Прочитай также [правила раннего завершения](../DUEL_EARLY_STOP.md).
4. [DATA_MODEL.md](../DATA_MODEL.md), все применимые [SQL-миграции](../../drizzle/)
   и затронутые серверные исходники.
5. [Клиентские типы API](../../src/shared/contracts/api.ts) и
   [runtime-валидаторы](../../src/shared/contracts/validate.ts).

При чтении через GitHub выбирай текущую `main`, если задача не задаёт другую
ветку. В рабочей копии сначала учитывай ветку, SHA и незакоммиченные изменения;
не делай pull/reset поверх чужой работы. Версию определяй по
[package.json](../../package.json) и [src/config.js](../../src/config.js).
Текст старого чата и отчёт выпуска не заменяют актуальные исходники. При
расхождении документации и кода выясни фактическое поведение и обнови контракт
в рамках задачи. Если доступа к репозиторию нет, прямо сообщи, что актуальный
контекст не прочитан.

## Что сохранять

- Единственный основной Worker и D1 определяются текущими конфигурацией и
  [SINGLE_SERVER.md](../SINGLE_SERVER.md). Сейчас API находится по адресу
  `https://movement-test-api-staging.rojoscarlos93.workers.dev/api`;
  `staging` — техническое имя. Не вводи вторую цель и не создавай пустую замену
  существующей базе. Архивная D1 бывшего сервера не обслуживает приложение.
- До явного гостевого входа `401 DEVICE_AUTH_REQUIRED` ожидаем. Публичный API
  использует Bearer-сессию устройства и не доверяет переданным клиентом
  идентификаторам владельца или тестовым заголовкам. Гостевая сессия может
  существовать без строки `profiles`; это допустимое состояние.
- Событие повторения имеет устойчивый UUID. Повтор доставки не увеличивает
  прогресс или награду второй раз. Клиент сначала сохраняет событие локально;
  завершение/прерывание раунда ждёт подтверждения очереди.
- В дуэли учитывается лучшая из трёх попыток. Ранний `abort` сохраняет
  подтверждённый положительный счёт для дуэли, оставаясь `aborted`. Рекорды и
  спортивный рейтинг требуют `completed` за полные 60000 мс. Не смешивай эти
  критерии и не суммируй попытки.
- Источник начислений и спортивных решений — серверные записи и правила.
  Агрегаты обслуживаются штатными SQL-триггерами и maintenance. Не меняй
  награды, пороги, длительности или версию правил без соответствующей задачи.
- Сервер не получает кадры, видео, звук и координаты и не доказывает
  физическое выполнение упражнения. Не добавляй такие поля ради отладки.
- Сохраняй API v1 для существующих APK и поведение v2, пока задача явно не
  меняет совместимость. Не подменяй сетевые ошибки переходом на старый API.
- Не выводи токены, имена, ссылки-приглашения, тела запросов и строки БД в
  логи, PR или диагностические артефакты. Секреты и незашифрованные закрытые
  ключи не должны попадать в git.

## SQL и миграции

Runtime ORM нет: используется SQL-first схема и параметризованные запросы
через `prepare().bind()`. Точная схема — результат всех актуальных
`drizzle/*.sql`; справочник модели находится в [DATA_MODEL.md](../DATA_MODEL.md).
Не редактируй применённую миграцию. Добавляй следующий файл, учитывая порядок
и метаданные, необходимые текущей сборке; правила исполнителей описаны в
[db/README.md](../../db/README.md).

Для новой миграции проверь как чистую БД, так и обновление БД с существующими
данными, конфликтами и повторным запуском штатного migrator. При изменении
производных таблиц продумай backfill из источника истины. Сохраняй FK, UNIQUE,
CHECK, идемпотентность и атомарность триггеров. Не заменяй базу, не исправляй
продакшен прямыми UPDATE и не запускай повторно исторические скрипты переноса
или отключения сервера без отдельной задачи.

`DB.batch()` атомарен, но весь HTTP-запрос или весь Cron не является одной
транзакцией. Оцени гонки до и после batch, повтор доставки, условные UPDATE и
ревизии `weekly_dirty`. Границы раунда и закрытия недели проверяй серверным
временем, включая окно доставки. Для спортивной недели используется
`Africa/Johannesburg`; дневной календарь определяется поясом профиля.

## Проверки и передача результата

Выбирай проверки, которые доказывают изменённое поведение. Основные наборы:

| Проверяемое поведение | Источники проверок |
| --- | --- |
| Запись, дубли, гонки, rollback, раунды и дуэли | [server.test.js](../../tests/server.test.js), [mvp-review.test.js](../../tests/mvp-review.test.js) |
| Недельные границы, бонусы, согласие и закрытие | [weeks.test.js](../../tests/weeks.test.js), [optimization.test.js](../../tests/optimization.test.js) |
| Публичная auth-граница и клиентская сессия | [cloudflare.test.js](../../tests/cloudflare.test.js), [device-client.test.js](../../tests/device-client.test.js) |
| Перезапуск Node и постоянная SQLite | [node-runtime.test.js](../../tests/node-runtime.test.js) |
| Контракт и внешние JSON-ответы | [client-contracts.test.js](../../tests/client-contracts.test.js), [api-client.test.js](../../tests/api-client.test.js) |
| Существующая основная D1 и цель деплоя | [backend-deploy.test.js](../../tests/backend-deploy.test.js) |

После адресных проверок выполни необходимые общие проверки из
[DEVELOPMENT.md](../DEVELOPMENT.md): `npm run typecheck`,
`npm run format:check`, `npm run lint`, `npm test`, `npm run build`,
`npm run backend:validate` и затронутые браузерные сценарии. Последняя команда
делает dry-run, публикации не выполняет. Пишущий smoke-тест
[local-worker-smoke.mjs](../../tests/local-worker-smoke.mjs) предназначен только
для изолированного локального Worker/D1; его нельзя направлять на основной API.

Передай Тимлиду: что изменилось для пользователя, какие файлы и контракт
затронуты, как сохраняются данные и совместимость, какие проверки реально
прошли, какие ограничения остались. Для миграции отдельно укажи порядок
применения и последствия неуспешного выпуска. Историческое число тестов не
является результатом проверки нового коммита.

Работай в отдельной временной ветке и подготовь PR. Слияние в `main`, remote-
миграции и публикацию выполняй только по прямой команде владельца для текущей
задачи. Локальную разрешённую работу доводи до готовности без промежуточных
запросов подтверждения.
