# Схема D1

Это SQL-first схема, runtime ORM нет. Первоначальная миграция находится в
[0000_squat_mvp.sql](../drizzle/0000_squat_mvp.sql); итоговая схема получается
применением всех актуальных [drizzle/*.sql](../drizzle/). Описание таблиц,
агрегатов, индексов и триггеров — [DATA_MODEL.md](../docs/DATA_MODEL.md).

Уже применённые миграции неизменяемы; следующие изменения добавляются отдельными
файлами с последующим номером. [meta/_journal.json](../drizzle/meta/_journal.json)
хранит метаданные набора миграций для используемой упаковки Sites. Он не является
универсальным исполнителем или источником порядка для всех сред:

- [Node/SQLite](../server/sqlite.js) читает все файлы `.sql` из `drizzle` и
  сортирует их имена лексикографически, журнал не читает. В служебной таблице
  `movement_migrations` сохраняет имя и SHA-256, отклоняя изменение уже
  применённого файла. Каждая новая миграция выполняется собственной
  транзакцией `BEGIN IMMEDIATE` с rollback при ошибке.
- Основная D1 обновляется механизмом миграций Wrangler. [Скрипт
  деплоя](../scripts/deploy-backend.mjs) сначала находит существующую основную
  базу, применяет `d1 migrations apply DB --remote` и затем публикует Worker.
  Его не запускают ради локальной проверки. Разрешение на remote-миграцию и
  публикацию задаёт владелец текущей задачи.
- [db:migrate:local](../scripts/dev-migrate.mjs) применяет миграции Wrangler
  только к локальной D1 из сгенерированной сборкой конфигурации.

Приложение никогда не создаёт таблицы при обработке HTTP-запросов. Node применяет
миграции при открытии локальной БД; HTTP может инициализировать строки настройки
и текущего недельного периода, но не схему. [Порядок разработки](../docs/DEVELOPMENT.md).

`repetition_events` имеет уникальный ключ пользователя и события. Триггер в той
же SQLite-транзакции увеличивает дневной прогресс и создаёт награду с уникальным
ключом дня. Награда, повтор события и обновление счётчика не могут разойтись при
одновременных запросах. Частичный уникальный индекс запрещает две активные
минутные попытки одного пользователя, в том числе с разных устройств.

Атомарность `DB.batch()` и триггеров не означает единую транзакцию всего
HTTP-запроса или Cron. Исходные события и награды сохраняются источником истины;
производные балансы и недельные максимумы поддерживают триггеры и maintenance.
При новой миграции проверяй чистую БД, обновление существующих данных и backfill.
