# Первый запуск «Движение Тест UI» 2.5.3

Новое тестовое приложение имеет отдельный пакет `com.movement.squat.staging.ui` и отдельный гостевой профиль. При первом открытии без входа API отвечает `401 DEVICE_AUTH_REQUIRED`: сервер доступен, но устройство ещё не создало сессию. Это не отказ камеры. Камера и модель запускаются действием пользователя в тренировке.

## Начать проверку

1. Закрыть панель диагностики, если она развёрнута.
2. Нажать **Быстрый старт (Гость)** либо ввести имя и нажать **Начать**.
3. Дождаться сообщения, что прогресс подтверждён сервером.
4. Открыть **Тренировка → Начать** и разрешить доступ к камере.

Создание профиля требуется один раз. Профиль сохраняется после перезапуска и обновления приложения с тем же пакетом и ключом. Выход из профиля, удаление приложения или очистка его данных меняют этот сценарий. Профили прежних приложений остаются отдельными.

## Исправления подсказок

- Ожидаемый первый ответ 401 сопровождается сообщением «Сервер доступен» и инструкцией гостевого входа.
- До входа кнопка в шапке называется «Создать профиль» и открывает карточку входа, вместо пустой формы редактирования.
- В диагностике есть переход «Создать профиль»: панель закрывается, карточка входа прокручивается в видимую область. Сессия автоматически не создаётся.
- Повторное подключение не предлагается как решение отсутствующего входа. Сетевые ошибки и ошибки сохранения сохраняют прежнюю обработку.
- В диагностическом отчёте остаются настоящие HTTP-статус и код сервера; авторизация и серверные ограничения не обходятся.

Браузерный сценарий проверяет начальный 401, обе кнопки перехода, отсутствие лишних POST до действия пользователя, успешный вход, сохранение профиля после перезапуска и дальнейшую тренировку через имитацию нативного HTTP-моста. Android-диалог разрешения и физическая камера Galaxy S23 требуют проверки на телефоне.

Изменения относятся к тестовой 2.5.3. Пакет, версия и постоянный ключ «Движение Тест UI» сохраняются; main, рабочий Worker/D1 и алгоритм распознавания не меняются.
