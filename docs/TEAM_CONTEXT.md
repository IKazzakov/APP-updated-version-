# Общий контекст команды «Движение»

Этот документ — вход в проект для Тимлида, Backend + БД и Frontend. Он
хранится в основном репозитории и читается вместе с корневым
[AGENTS.md](../AGENTS.md). Копии из старого чата, локальный ZIP или файл
из чужой рабочей среды для начала работы не нужны.

Общий план развития, статусы десяти этапов и ближайшая контрольная точка —
в [ROADMAP.md](ROADMAP.md). Перед выбором следующей задачи сверяй его с актуальной
main и веткой реализации; «реализовано в PR» не означает «выпущено».

## Как получить актуальные инструкции

1. Проверь доступ к приватному `rojoscarlos-cpu/APP-updated-version-`
   через подключённый GitHub или локальную рабочую копию. Не считай
   видимость URL доказательством чтения: получи содержимое файла инструментом.
2. Определи текущий SHA `main`, версию из [package.json](../package.json)
   и [src/config.js](../src/config.js). Для локальной копии также проверь
   ветку, SHA и незакоммиченные изменения; не затирай их ради обновления.
3. Прочитай AGENTS.md, этот файл, [API](API.md), [разработку](DEVELOPMENT.md),
   [единственный сервер](SINGLE_SERVER.md) и документ своей роли:
   [Тимлид](team/TEAMLEAD.md), [Backend + БД](team/BACKEND.md),
   [Frontend](team/FRONTEND.md).
4. Прочитай связанные исходники, клиентские типы/валидаторы и миграции
   по задаче. Относительные ссылки разрешай от расположения файла в том же
   репозитории и выбранной ревизии; через GitHub явно выбирай ref.
5. Кратко сообщи владельцу фактически прочитанный SHA/версию, роль и
   обнаруженные блокеры доступа. Не проси ручную копию доступного файла.

Перед следующей задачей или после восстановления контекста проверь, не
изменились ли исходная ревизия и нужные документы. Для согласованной задачи
в отдельной ветке учитывай её diff относительно main. Не фиксируй выпуск,
SHA, число тестов или текст этого документа навсегда в стартовом промпте.

Обычный чат читает файлы по стартовой инструкции и только при наличии
доступных GitHub-инструментов/рабочей копии. Файл в приватном GitHub сам по
себе не подключает инструменты к будущему чату. Если доступа нет, назови
конкретно недоступный репозиторий/инструмент и необходимое подключение;
не запрашивай токен в чате и не выдавай старый снимок за актуальный.

## Технологии и границы

| Слой | Реализация и источник |
| --- | --- |
| Клиент | ES Modules, JavaScript + постепенно внедряемый TypeScript, Vite; версии в package.json |
| UI | HTML-фрагменты, DOM и CSS; SVG-график, Canvas overlay. React/UI-kit/сторонней библиотеки состояния нет |
| Типизация | [tsconfig.json](../tsconfig.json): strict для TS, allowJs=true/checkJs=false; старый JS не весь строго проверяется |
| Android | Capacitor, установленный пакет com.movement.squat.staging.ui; [подпись](ANDROID_SIGNING.md) |
| Распознавание | MediaPipe Tasks Vision, Pose Landmarker Full, локальные модель/WASM и vision.worker.js |
| Backend | JavaScript ES Modules, Cloudflare Workers; локально Node.js и node:sqlite |
| БД | D1/SQLite, параметризованный SQL prepare/bind и batch; runtime ORM отсутствует |
| Миграции | [drizzle/](../drizzle) — SQL-first миграции, а не Drizzle ORM; [модель данных](DATA_MODEL.md) |
| Публикация | [четыре постоянных workflow](../.github/workflows), один основной сервер, ручной deploy из main |

Клиентские границы:

```text
Feature → SessionService → API client → transport
                                ↓ runtime-проверка JSON
                              AppStore → UI

Повторение → устойчивый UUID → локальная IndexedDB → отправка
           → подтверждение очереди → finish/abort
```

Основные каталоги:

| Каталог | Ответственность |
| --- | --- |
| src/app | bootstrap, registry, navigation, AppStore |
| src/features | profile, today, training, progress, competitions |
| src/services | SessionService, API client, RoundPersistence |
| src/shared/contracts | wire-типы и runtime-валидация внешнего JSON |
| src/diagnostics | единый координатор диагностики |
| src/algorithms и существующие src/*.js | камера, модель, подсчёт, платформа, Outbox, транспорт |
| server | публичная авторизация, маршруты, SQL-чтения, правила, недели, maintenance, локальный адаптер |
| drizzle, db | миграции и пояснения к схеме |
| public, android | локальные ресурсы распознавания, APK/метаданные и Capacitor-проект |
| scripts, tests | сборка, проверки, миграции, деплой и тестовые сценарии |
| docs | текущие контракты/инструкции и явно исторические отчёты |

## Общие инварианты

- Единственный основной API:
  `https://movement-test-api-staging.rojoscarlos93.workers.dev/api`.
  `staging` — техническое имя. Worker movement-test-api удалён, его D1
  сохранена архивом; отдельного тестового backend в текущем процессе нет.
- Сохраняй Android-пакет, прежний ключ и API-base: device-secret, Outbox
  и восстановление привязаны к адресу API и профилю. Настройка соединения
  находится в общей диагностике.
- Первый вход явный гостевой. `401 DEVICE_AUTH_REQUIRED` до него ожидаем.
  Публичный API определяет владельца по индивидуальной Bearer-сессии;
  имя и переданные клиентом заголовки не доказывают идентичность.
- Повторение сохраняется локально до отправки с тем же UUID при повторах.
  finish/abort ждут подтверждения очереди. Не терять/не перепривязывать
  неподтверждённые записи при смене профиля, сервера и сетевых ошибках.
- Правила squat-v1: 60000 мс на раунд, 15000 мс на доставку, один active
  на пользователя. Истечение таймера автоматически completed не создаёт.
- Дуэль: по три начатые попытки, лучшая попытка; положительный count,
  подтверждённый до abort, учитывается. aborted остаётся aborted и не
  создаёт личный минутный рекорд или спортивный рейтинг.
- Дневная цель 10/+10, полная неделя +20, спортивные места +20/+10/+5;
  при равных местах полная награда каждому. День — IANA-пояс профиля,
  спортивная неделя — Africa/Johannesburg. Начисления делает сервер.
- Видео, звук и координаты не отправляются. Не менять модель/WASM,
  пороги и начисления без соответствующей задачи.
- Применённые SQL-миграции неизменяемы. Не создавать пустую замену
  существующей основной D1. Агрегаты не являются независимой историей.

## Совместная работа и актуальность

Три чата не имеют общей памяти и не получают результаты друг друга
автоматически. Общие принятые решения и инструкции должны быть доступны
в GitHub; в задании указываются ветка/PR/SHA, если результат ещё не в main.
Не утверждай, что другой чат получил или согласовал решение, без факта передачи.

Тимлид выдаёт пакет: ID задачи, базовый SHA, наблюдаемая цель, контракт и
его изменения, владелец общих типов/валидаторов, границы файлов, зависимости,
критерии приёмки, необходимые проверки. Исполнитель возвращает PR/SHA,
конечное поведение, изменения контракта/схемы, выполненные проверки и ограничения.

Один назначенный исполнитель меняет общие api.ts/validate.ts; Backend и
Frontend не создают два несовместимых варианта одного контракта. Изменение
API сопровождается обновлением [API.md](API.md), типов, валидаторов и
затронутых проверок в том же PR. Расхождения не замалчиваются: отличай
существующее поведение от предложения и от доказанного бага.

Работай в отдельных временных ветках, сохраняя чужие изменения.
Слияние main и публикация — по прямой команде владельца соответствующей
задачи; после разрешённого слияния удаляются только ветки с проверенно
сохранёнными в main коммитами. Изменять исходный Test не нужно.
Не коммитить/не выводить секреты и незашифрованные закрытые ключи.

## Проверки и подтверждённый статус

Команды и среда перечислены в [DEVELOPMENT.md](DEVELOPMENT.md). Подбирай
проверки по задаче: typecheck, format:check, lint, npm test, build,
backend:validate (dry-run), соответствующие browser-сценарии. Для правок
только документации проверь ссылки, пути, точность инструкций и diff;
не называй это новой проверкой камеры или runtime API.

Последний подтверждённый функциональный выпуск —
[2.5.4](releases/2.5.4-2026-10-23.md): 222 unit/integration-теста,
47 браузерных сценариев, подписанный APK и основной deploy успешны.
Это историческая проверка указанного выпуска; фактический результат новой
задачи указывается отдельно. Реальная камера и производительность Galaxy S23
подтверждаются на устройстве.

[Три стартовых промпта](team/START_PROMPTS.md) используются один раз;
дальнейшие инструкции и контракты читаются из этого репозитория.
