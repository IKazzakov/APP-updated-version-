## Цель, контракт и границы

Цель: вернуть совместимые workout-маршруты на единственном основном сервере
и доставить сохранённую программу без удаления/перепривязки очереди.

Проверяемый код уже есть в [кандидате 2.6.1](2.6.1-rc-2026-10-27.md):
393 PASS / 1 SKIP / 0 FAIL, браузеры 56/56, подписанный APK получен и проверен.
В этой задаче не требуется новый алгоритм, API-контракт или самостоятельная
пересборка ещё одного тестового APK. Штатный финальный release workflow использует
артефакты своего итогового main SHA; установленный APK 2.6.1 совместим с этим контрактом.

HTTP-входы/выходы/auth/ошибки/UUID/окна/пагинация/ревизии сохраняются согласно
[API.md](../API.md). Для профиля catalog/activity/history должны вернуть 200 и
валидные workout-v1/activity-v1 JSON; без auth 401 DEVICE_AUTH_REQUIRED,
без профиля 409 PROFILE_REQUIRED; private/no-store. Никакого fallback на v1.
sync и pendingEnd повторяются с прежними ID/временем, finish/abort ждут ack.
Общие wire-типы/валидаторы закреплены за Backend и не требуют изменения.

Используется только Worker movement-test-api-staging и существующая D1
movement-test-app-staging. Не создавать другую базу/сервер, не менять пакет/ключ,
API-base, auth scope, распознавание или XP; 0000–0005 не редактировать.
Не удалять профиль/локальный журнал, не отзывать пользовательскую сессию.
